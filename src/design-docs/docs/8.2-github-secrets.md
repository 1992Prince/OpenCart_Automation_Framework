
## GitHub Actions Secrets

We can create secrets at **two levels**:

### 1. Repository-Level Secrets

* Repository-level secrets are created at the repository level.
* They are useful for common secrets that can be used across workflows/environments.
* Example:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Run tests
        run: npx playwright test
        env:
          APP_BASE_URL: ${{ secrets.APP_BASE_URL }}
          APP_USERNAME: ${{ secrets.APP_USERNAME }}
          APP_PASSWORD: ${{ secrets.APP_PASSWORD }}
```

Here, the secrets are directly fetched from **Repository Secrets**.

---

### 2. Environment-Level Secrets

We can create separate GitHub Environments such as:

```text
QA
Stage
Dev
```

Each environment can have different secrets.

Example:

```text
QA
  APP_BASE_URL = https://qa.example.com
  APP_USERNAME = qa_user

Stage
  APP_BASE_URL = https://stage.example.com
  APP_USERNAME = stage_user
```

#### YAML

When using environment-level secrets, associate the job with the required GitHub Environment:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    environment: QA

    steps:
      - name: Run tests
        run: npx playwright test
        env:
          APP_BASE_URL: ${{ secrets.APP_BASE_URL }}
          APP_USERNAME: ${{ secrets.APP_USERNAME }}
          APP_PASSWORD: ${{ secrets.APP_PASSWORD }}
```

Here:

```yaml
environment: QA
```

associates the job with the **QA GitHub Environment**.

Then:

```yaml
${{ secrets.APP_BASE_URL }}
```

can resolve the `APP_BASE_URL` secret configured for that environment.

---

### Difference in YAML

**Repository-level secrets:**

```yaml
jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Run tests
        env:
          APP_BASE_URL: ${{ secrets.APP_BASE_URL }}
          APP_USERNAME: ${{ secrets.APP_USERNAME }}
```

**Environment-level secrets:**

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    environment: QA

    steps:
      - name: Run tests
        env:
          APP_BASE_URL: ${{ secrets.APP_BASE_URL }}
          APP_USERNAME: ${{ secrets.APP_USERNAME }}
```

### Important Difference

The main YAML difference is:

```yaml
environment: QA
```

For **Repository Secrets**, we don't need to specify a GitHub Environment.

For **Environment Secrets**, we associate the job with the required GitHub Environment.

### Interview Answer

> **"GitHub Actions supports repository-level and environment-level secrets. Repository secrets are useful for common configuration, while environment secrets allow us to maintain different values for QA, Stage, and Dev. In the workflow, we associate the job with the required environment using the `environment` property and access the secrets using `${{ secrets.SECRET_NAME }}`."**
