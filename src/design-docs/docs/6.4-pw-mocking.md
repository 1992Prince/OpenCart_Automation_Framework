# Playwright Network Interception and Mocking

## Interception Basics

**What is Interception?**
- Capturing/intercepting network requests that a web application makes in the background
- Browser makes multiple requests to APIs, JS files, images, CSS, etc.
- Playwright allows interception using `page.route()`

**Basic Syntax**
```javascript
await page.route('URL_PATTERN', async (route) => {
    // inspect or modify the request
});
```
- `route` = current network request Playwright intercepted
- Can name the parameter anything, but `route` is convention

---

## URL Patterns

**Intercept All Requests**
```javascript
await page.route('**/*', async (route) => {
    // intercept every request
});
```

**Intercept Specific URL**
```javascript
await page.route('**/opencart/index.php?route=common/home', async (route) => {
    // only this URL pattern
});
```

---

## Getting Request Details

**Available Methods**
- `route.request().method()` → Get HTTP method (GET, POST, etc.)
- `route.request().url()` → Get request URL

**Example**
```javascript
await page.route('**/*', async (route) => {
    console.log(
        "Request:",
        route.request().method(),
        route.request().url()
    );

    await route.continue();
});
```

---

## Intercept vs Mock

**Intercept** = Capture/inspect/modify a real network request
**Mock** = Prevent real request from reaching server, return custom response

**Getting Real Response While Inspecting**
```javascript
const response = await route.fetch();

console.log("Status:", response.status());
console.log("Body:", await response.text());
```
- `route.fetch()` performs actual network request and gives response

---

## Simple Example — Log Request + Response

```javascript
import { test } from '@playwright/test';

test('Intercept network calls', async ({ page }) => {

    await page.route('**/*', async (route) => {

        // Request details
        console.log(
            'Request:',
            route.request().method(),
            route.request().url()
        );

        // Make the actual network request
        const response = await route.fetch();

        // Response details
        console.log('Response Status:', response.status());
        console.log('Response Body:', await response.text());

        // Continue with the actual response
        await route.fulfill({
            response
        });
    });

    await page.goto('https://example.com');
});
```

## Playwright Mocking vs WireMock

**Playwright Mocking**
- Built directly into Playwright
- Uses `page.route()` / routing APIs
- Can intercept requests and return mocked responses
- Useful for: API failures, specific response data, slow responses
- Best for: Browser-level scenarios

**WireMock**
- Separate HTTP mock server (external tool)
- Runs independently of Playwright
- Useful when: need reusable mock service for API/integration testing

---

## Mocking API Response

**What is Mocking?**
- Intercept real API request and don't allow it to reach actual server
- Playwright returns fake/custom response we provide
- Useful when:
  - Real API unavailable
  - Don't want to depend on backend data
  - Need predictable test data
  - Want to test different scenarios (success, empty, 404, 500, etc.)

**Using `route.fulfill()`**
```javascript
await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify(fakeProducts)
});
```
- Tells Playwright: Don't send to real server, return this response instead

**Full Example — Mock Search API**
```javascript
test('mock search data api', async ({ page }) => {

    const fakeProducts = [
        { name: 'Macbook Pro', price: '$599' },
        { name: 'Macbook Air M5', price: '$499' },
        { name: 'Macbook M4', price: '$399' },
        { name: 'Macbook Neo', price: '$299' }
    ];

    await page.route(
        '**/index.php?route=product/search&search=macbook',
        async (route) => {

            await route.fulfill({
                status: 200,
                contentType: 'application/json',
                body: JSON.stringify(fakeProducts)
            });
        }
    );

    await page.goto(
        'https://abc.com/index.php?route=product/search&search=macbook'
    );

    await page.pause();
});
```

**Flow**
- `page.route()` registers handler for URL pattern `**/index.php?route=product/search&search=macbook`
- `**` means baseURL can be anything
- Intercepts matching request
- Real API/server NOT called
- `route.fulfill()` returns fake response
- Browser receives mocked JSON

---

## route.continue() vs route.fulfill() vs route.fetch()

- `route.continue()` → Request goes to **real server**
- `route.fulfill()` → Request **mocked**, custom response returned
- `route.fetch()` → Makes **real network request**, gives us response

## Realistic Use Cases

### 1) Backend Still Under Development — Shift Left Testing

**Scenario**
- Frontend/dev and backend teams agree on API contract (Swagger/OpenAPI, Confluence)
- Frontend development complete, but backend API still under development
- Frontend normally calls real backend, but it's not ready yet

**Solution**
- QA/SDET doesn't wait for backend completion
- Use Playwright mocking:
  - Intercept API call browser will make
  - Read expected response structure from contract/Swagger
  - Return mocked response matching contract
  - Continue UI automation development
- Once backend ready, same tests run against real API (E2E/integration testing)

**Benefit**
- QA starts automation in parallel with backend development, not waiting

### 2) Test API Error Scenarios (500, 404, etc.)

**Scenario**
- Real systems don't always return 200
- Need to verify UI behavior for error responses: 400, 401, 403, 404, 500, etc.

**Example — Mock 500 Error**
```javascript
await page.route('**/*', async (route) => {

    await route.fulfill({
        status: 500,
        contentType: 'application/json',
        body: JSON.stringify({
            message: 'Internal Server Error'
        })
    });

});
```

**Benefits**
- `**/*` intercepts all matching requests
- Request doesn't reach real server
- Playwright returns mocked 500
- Can verify response in browser's Network tab
- If app displays API error on UI, verify user sees message

**Why Mock?**
- Creating real 500 in test environment difficult/unreliable
- Mocking is consistent and controllable

### 3) Test Slow API Responses / Loading Spinner

**Scenario**
- Requirement: If API takes 5 seconds, loading spinner should remain visible until response

**Solution**
```javascript
await page.route('**/*', async (route) => {

    await page.waitForTimeout(5000);

    await route.continue();

});

await page.goto(
    'https://naveenautomationlabs.com/opencart/index.php?route=common/home'
);

await page.pause();
```

**How It Works**
- Playwright intercepts request
- Waits 5 seconds
- Then allows request to continue to real server
- During wait, verify loading spinner displayed

**Note**
- This is **network interception/delay**, not API mocking
- `route.fulfill()` → Mock response
- `route.continue()` → Send to real server
- `route.fetch()` → Make real request and get response

---

## Key Distinctions

- **route.fulfill()** → Mock the response
- **route.continue()** → Send request to real server  
- **route.fetch()** → Make real request and get response
