# GitHub Actions — Workflow & Pipeline Basics

## 1. Basic Workflow Concept

A **GitHub Actions workflow** is a YAML file that defines the steps to execute automatically or manually.

- A GitHub Actions workflow is a YAML file used to automate a specific task.

- For QA automation, a basic workflow usually looks like:

**Checkout → Install → Cache → Run Tests**

Example:

```text
Checkout code
     ↓
Install dependencies
     ↓
Cache Playwright browsers/dependencies
     ↓
Run tests
```

We can also trigger workflows:

* **On demand** using `workflow_dispatch`
* **On code push** using `push`
* **On pull request** using `pull_request`
* **On schedule** using a cron expression

For example, a cron can run regression tests at a scheduled time.

---

# 2. Workflow vs Pipeline

- A **workflow** can perform one specific activity.
- e.g. A **workflow** can simply run QA tests.

Example:

> QA manually selects `QA` environment → workflow runs regression tests.

A **pipeline** represents the complete CI/CD flow from application build to deployment and testing.
- A CI/CD pipeline represents the complete application deplivery flow.

### Basic Pipeline

```text
Build → Test → Deploy → Test → Deploy → Test
```

The pipeline can connect **development and QA activities**.

---

# 3. Typical CI/CD Pipeline

The typical CI/CD pipeline can be structured as follows:

```text
1. Build Application
   → Build the application
   → Run Unit Tests
   → Run Integration Tests

2. Deploy to DEV
   → Deploy the application to DEV
   → Run Sanity / Smoke UI Tests

3. Deploy to QA
   → Deploy the application to QA
   → Run Smoke Tests
   → Run Regression Tests

4. Deploy to STAGE / UAT
   → Deploy the application to STAGE / UAT
   → Run Sanity Tests

5. Deploy to PROD
   → Deploy the application to PROD
   → Run basic Smoke / Health Check tests

6. Pipeline Summary
   → Display build, deployment and test execution status
   → Show which stages passed, failed or were skipped
```

The exact test strategy can vary by project. 

---

# 4. Dev Repo and QA Automation Repo

Usually, development and QA automation can be maintained in **separate repositories**.

### Development Repo

Contains:

* Application source code
* Unit tests
* Integration tests

Example stack:

```text
Java + Maven
```

### QA Automation Repo

Contains:

* UI automation
* API automation
* Test framework
* Test configuration

Example:

```text
Playwright + TypeScript
```

Keeping separate repositories is useful when the two projects have different technology stacks and release/maintenance needs.

**Unit and integration tests written by developers can remain in the development repository** because they directly test the application code.

In the example pipeline, the application is checked out from the development repository, while Playwright tests are checked out from the QA repository.

# 5. Test Execution Strategy

Tests can be categorized using tags.

```text
@smoke
@sanity
@regression
```

Then GitHub Actions can execute only the required tests.

### Smoke

Small set of **critical tests** to verify that the application is basically working.

```bash
npx playwright test --grep @smoke
```

### Sanity

Focused tests covering the **important functionality after a change/deployment**.

### Regression

Broader suite covering the application's **existing functionality/user journeys**.

Example from the pipeline:

```bash
npx playwright test --project=chromium --grep @smoke
```

and:

```bash
npx playwright test --project=chromium --grep @regression
```

- We can also specify a particular Playwright project: npx playwright test --project=chromium --grep @smoke

- These commands can be added to package.json scripts and then called from the GitHub Actions YAML.

---

# 6. Environment-wise Execution

A common strategy can be:

| Environment | Typical Testing     |
| ----------- | ------------------- |
| DEV         | Sanity              |
| QA          | Regression          |
| STAGE/UAT   | Sanity              |
| PROD        | Smoke/Health checks |

In the example workflow:

```text
DEV   → Sanity
QA    → Regression
STAGE → Sanity
PROD  → Smoke
```

# 7. Pipeline with Environment Selection

A pipeline can also allow the user to select **how far the pipeline should run**.

For example:

```text
dev
QA
stage
Prod
```

If user selects:

### DEV

```text
Build → DEV → Sanity
```

### QA

```text
Build → DEV → Sanity
             ↓
             QA → Regression
```

### STAGE

```text
Build → DEV → QA → STAGE
```

### PROD

```text
Build → DEV → QA → STAGE → PROD
```

The example workflow implements this using a `workflow_dispatch` environment input and conditional jobs.  

---

# 8. Simple Interview Explanation

> **A GitHub Actions workflow is used to automate a particular activity, such as running smoke or regression tests. A CI/CD pipeline is a broader flow where the application is built, tested and deployed across environments. For example, after developers push code, the pipeline can build the application and run unit/integration tests, deploy it to DEV and trigger QA sanity tests. It can then move to QA for regression, STAGE/UAT for focused validation, and finally PROD with basic smoke or health checks. QA automation can be maintained in a separate repository and triggered from the pipeline using environment-specific test tags.**

This is the **basic pipeline concept** you should be comfortable explaining before going into advanced GitHub Actions concepts.

# 9. Sample pipeline.yml

```
name: CI-CD Pipeline

on:
  workflow_dispatch:
    inputs:
      environment:
        description: "Run pipeline up to environment"
        required: true
        type: choice
        options:
          - dev
          - qa
          - stage
          - prod
        default: qa

jobs:

  # --------------------------------
  # 1. BUILD + UNIT TESTS
  # --------------------------------
  build:
    name: Build Application
    runs-on: ubuntu-latest

    steps:

      - name: Checkout Application Code
        uses: actions/checkout@v4

      - name: Setup Java
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "17"

      - name: Build and Run Unit Tests
        run: |
          mvn clean install


  # --------------------------------
  # 2. DEPLOY TO DEV
  # --------------------------------
  deploy-dev:
    name: Deploy to DEV
    needs: build
    runs-on: ubuntu-latest

    steps:

      - name: Deploy Application to DEV
        run: echo "Deploying application to DEV"


  # --------------------------------
  # 3. SANITY TESTS ON DEV
  # --------------------------------
  sanity-dev:
    name: DEV Sanity Tests
    needs: deploy-dev
    runs-on: ubuntu-latest

    steps:

      - name: Checkout QA Automation Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Install Dependencies
        run: npm ci

      - name: Run DEV Sanity Tests
        run: |
          npx playwright test --project=chromium --grep @sanity
        env:
          ENV: dev


  # --------------------------------
  # 4. DEPLOY TO QA
  # --------------------------------
  deploy-qa:
    name: Deploy to QA
    needs: sanity-dev
    if: contains(fromJSON('["qa","stage","prod"]'), github.event.inputs.environment)
    runs-on: ubuntu-latest

    steps:

      - name: Deploy Application to QA
        run: echo "Deploying application to QA"


  # --------------------------------
  # 5. REGRESSION TESTS ON QA
  # --------------------------------
  regression-qa:
    name: QA Regression Tests
    needs: deploy-qa
    if: contains(fromJSON('["qa","stage","prod"]'), github.event.inputs.environment)
    runs-on: ubuntu-latest

    steps:

      - name: Checkout QA Automation Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Install Dependencies
        run: npm ci

      - name: Run Regression Tests
        run: |
          npx playwright test --project=chromium --grep @regression
        env:
          ENV: qa


  # --------------------------------
  # 6. DEPLOY TO STAGE
  # --------------------------------
  deploy-stage:
    name: Deploy to STAGE
    needs: regression-qa
    if: contains(fromJSON('["stage","prod"]'), github.event.inputs.environment)
    runs-on: ubuntu-latest

    steps:

      - name: Deploy Application to STAGE
        run: echo "Deploying application to STAGE"


  # --------------------------------
  # 7. SANITY TESTS ON STAGE
  # --------------------------------
  sanity-stage:
    name: STAGE Sanity Tests
    needs: deploy-stage
    if: contains(fromJSON('["stage","prod"]'), github.event.inputs.environment)
    runs-on: ubuntu-latest

    steps:

      - name: Checkout QA Automation Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Install Dependencies
        run: npm ci

      - name: Run Sanity Tests
        run: |
          npx playwright test --project=chromium --grep @sanity
        env:
          ENV: stage


  # --------------------------------
  # 8. DEPLOY TO PROD
  # --------------------------------
  deploy-prod:
    name: Deploy to PROD
    needs: sanity-stage
    if: github.event.inputs.environment == 'prod'
    runs-on: ubuntu-latest

    steps:

      - name: Deploy Application to PROD
        run: echo "Deploying application to PROD"


  # --------------------------------
  # 9. PROD SMOKE TESTS
  # --------------------------------
  smoke-prod:
    name: PROD Smoke Tests
    needs: deploy-prod
    if: github.event.inputs.environment == 'prod'
    runs-on: ubuntu-latest

    steps:

      - name: Checkout QA Automation Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Install Dependencies
        run: npm ci

      - name: Run PROD Smoke Tests
        run: |
          npx playwright test --project=chromium --grep @smoke
        env:
          ENV: prod
```
