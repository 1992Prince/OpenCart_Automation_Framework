# Playwright API Automation Guide

## First time clone and setup commands

```bash
npm install
npx playwright install
npx playwright test tests/
```

---

## 1. Playwright API Automation

- **Playwright** supports both Web UI + API automation
- **Selenium** primarily supports Web UI automation only
- Playwright can make REST API calls using HTTP methods:
  - GET
  - POST
  - PUT
  - PATCH
  - DELETE

---

## 2. Request Fixture

Playwright provides an inbuilt `request` fixture of type `APIRequestContext`.

Direct methods available:
- `request.get(url, options)`
- `request.post(url, options)`
- `request.put(url, options)`
- `request.patch(url, options)`
- `request.delete(url, options)`

**Example:**
```javascript
test('API Test', async ({ request }) => {
    const response = await request.get('https://example.com/users');
});
```

Simply destructure the `request` fixture and use its HTTP methods.

---

## 3. UI + API in Same Test

Playwright allows UI and API automation in the same test.

```javascript
test('UI with API automation', async ({ page, request }) => {
    await page.goto('https://example.com');
    const response = await request.get('https://example.com/api/users');
});
```

- `page` → Web UI/browser automation
- `request` → API automation

**Test Types:**
- UI-only tests
- API-only tests
- UI + API combined tests

## 4. CRUD Operations

| Operation | HTTP Method |
|-----------|------------|
| Create    | POST       |
| Retrieve  | GET        |
| Update    | PUT / PATCH|
| Delete    | DELETE     |

**API request generally contains:**
- URI + Endpoint
- Headers
- Request Body (where required)

---

## 5. HTTP Methods

### GET — Retrieve
- URI + endpoint
- Query/path parameters if required
- Headers + authentication
- Generally no request body
- Common success response: `200 OK`

### POST — Create
- URI + endpoint
- Headers + authentication
- Request body/payload (usually JSON)
- Common success response: `201 Created`

### PUT — Update/Replace
- URI + endpoint
- Headers + authentication
- Request body/payload
- Generally returns a `2xx` response

### PATCH — Partial Update
- URI + endpoint
- Headers + authentication
- Request body/payload
- Generally returns a `2xx` response

### DELETE — Delete
- URI + endpoint (often with resource ID/path parameter)
- Headers + authentication
- Usually no request body
- Common response: `204 No Content`

## 6. Bearer Token Authentication

Token-based authentication is commonly passed through the `Authorization` header:

```
Authorization: Bearer <token>
```

- **Key:** `Authorization`
- **Value:** `Bearer <token>`

`Bearer` indicates that the token is being presented as the authentication credential.

## 7. JSON Basics

### A. JSON Object

A JSON object is written using `{ }`. It contains key-value pairs.

```json
{
  "name": "John",
  "age": 30,
  "city": "Delhi"
}
```

**Rules:**
- Keys must always be strings and must be enclosed in double quotes
- JSON values can be: String, Number, Boolean, Array, Object, null

**Extended Example:**
```json
{
  "name": "John",
  "age": 30,
  "isActive": true,
  "skills": ["Java", "Playwright"],
  "address": {
    "city": "Delhi"
  },
  "middleName": null
}
```

**Important:** JSON does not support functions, undefined, or other JavaScript-specific values.

### B. JSON Array

A JSON array is written using `[ ]`. It can contain:
- Single value
- Multiple values
- Multiple objects
- Multiple arrays
- A combination of valid JSON values

**Array of strings:**
```json
[
  "Java",
  "JavaScript",
  "Playwright"
]
```

**Array of JSON objects:**
```json
[
  {
    "name": "John",
    "age": 30
  },
  {
    "name": "David",
    "age": 25
  }
]
```

**Mixed types:**
```json
[
  "John",
  30,
  true,
  null,
  {
    "city": "Delhi"
  }
]
```

### C. Complex Object with Array and Nested Object

```json
{
  "name": "John",
  "age": 30,
  "address": {
    "city": "Delhi",
    "country": "India"
  },
  "skills": [
    "Java",
    "Playwright"
  ]
}
```

**Array containing objects:**
```json
{
  "name": "John",
  "skills": [
    {
      "name": "Java",
      "experience": 5
    },
    {
      "name": "Playwright",
      "experience": 3
    }
  ]
}
```

## 8. JavaScript Object vs JSON Object

## Overview
- JSON and JavaScript Objects are both used to represent data in JavaScript, but they are designed for different use cases
- JSON focuses on data exchange, while JavaScript Objects are meant for working with data inside programs
- JSON is a text-based format used for storing and transmitting data, whereas JavaScript objects exist in memory and are used for program logic
- JavaScript Objects can include methods and complex logic, but JSON is limited to pure data only

## JavaScript Objects

- A data structure in JavaScript used to store key–value pairs
- Keys are usually strings (or Symbols), and values can be any type (number, string, array, function, another object, etc.)
- Keys can be written without double quotes (optional)
- Keys that contain spaces or special characters should be quoted
- Objects exist in memory during program execution
- Can contain functions and methods for complex logic
- Used for working with data inside programs

**Example:**
```javascript
const user = {
    name: "Amit",
    age: 25,
    city: "Mumbai",
    greet: function () {
        console.log(`Hello, ${this.name}!`);
    },
};
```

- Here `user` is a JS object reference
- `name`, `age`, `city`, `greet` are keys stored as strings
- `greet` is a method (function) - not allowed in JSON

## JSON (JavaScript Object Notation)

- A text-based data format designed for data exchange
- Language-independent and follows a strict syntax for storing and transmitting data
- Data is stored in files with `.json` extension
- JSON object keys can ONLY be strings. Keys must always be enclosed in double quotes.
- JSON does NOT support numbers as keys. JSON does NOT support any other data type as keys
- Values can be of types: string, number, boolean, arrays, objects, null
- Strings must be enclosed in double quotes
- Used for transferring data between servers and applications
- Cannot contain functions or methods

**Example:**
```json
{
    "name": "Amit",
    "age": 25,
    "city": "Mumbai"
}
```

## Automatic Conversions in Playwright

### Sending Data to Server (JavaScript Object → JSON)
- If you keep test data in a JS object, pass it directly to a POST request
- Playwright automatically converts the JS object to JSON format and sends data to server
- No manual serialization needed

**Example:**
```javascript
const userData = { name: "Rahul", age: 28 };
const response = await request.post('https://api.example.com/users', {
    data: userData // Playwright converts to JSON automatically
});
```

### Receiving Data from Server (JSON → JavaScript Object)
- Once you receive response, use `response.json()` method to fetch the body
- Playwright automatically converts JSON data into JS object
- No manual deserialization needed
- `response.json()` returns in JS object form
- UI can access internal data using dot notation

**Example:**
```javascript
const response = await request.get('https://api.example.com/users/1');
const user = await response.json(); // Auto-converts to JS object
console.log(user.name); // Access using dot notation
```

## Manual JSON Conversions

### JavaScript Object to JSON String (Serialization)
- Use `JSON.stringify()` to convert JavaScript Objects into JSON strings
- Useful when you need to store JS object as a string or manually prepare JSON payload

**Example:**
```javascript
const user = { name: "Rahul", age: 28 };
const jsonStr = JSON.stringify(user);
console.log(jsonStr); // {"name":"Rahul","age":28}
```

### JSON String to JavaScript Object (Deserialization)
- Use `JSON.parse()` to convert JSON strings into JavaScript Objects
- Useful when you read JSON from files or APIs and need to work with it as an object

**Example:**
```javascript
const jsonStr = '{"name": "Neha", "age": 30}';
const obj = JSON.parse(jsonStr);
console.log(obj.name); // "Neha"
```

## Working with JSON Files

### Importing JSON Files
- JSON works naturally with JS/TS Node
- No third-party library required for basic JSON operations
- When you import a JSON file, it's automatically parsed as a JS object

**Example:**
```javascript
const testData = require('./data.json'); // Automatically parsed
```

### Reading JSON Files with fs Module
- Use `fs.readFileSync('path', 'utf-8')` to read JSON files
- This reads the file as a JSON string format (not automatically parsed)
- You need to manually convert it to a JS object using `JSON.parse()`

**Example:**
```javascript
const fs = require('fs');
const dataStr = fs.readFileSync('data.json', 'utf-8'); // JSON string
const dataObj = JSON.parse(dataStr); // Convert to JS object
console.log(dataObj.name); // Now you can access properties
```

### Direct Import vs fs.readFileSync
- **Direct import** (`require()`) → Automatically returns JS object
- **fs.readFileSync()** → Returns JSON string format, needs `JSON.parse()` to convert

---

**Key Takeaway:**
- JavaScript Objects = In-memory, can have methods, used in code logic
- JSON = Text format, no methods, used for data transfer and storage
- Playwright handles most conversions automatically, but understand both for manual scenarios
