Understand the YAML from Top to Bottom
==========================================

        name
        ↓
        on
        ↓
        jobs
        ↓
        runs-on
        ↓
        environment
        ↓
        steps
        ↓
        uses / run
        ↓
        env
        ↓
        artifacts


name
    Workflow name displayed in GitHub Actions.
    name: Playwright Tests

on
    Defines when the workflow should execute.

    on:
    push:
    pull_request:
    schedule:
    workflow_dispatch:


jobs
    Defines the work to perform.

    jobs:
    test:

runs-on
    Defines the runner/OS. = runs-on: ubuntu-latest

timeout-minutes
    Prevents a job from running indefinitely.
    timeout-minutes: 15

environment
    Selects the GitHub Environment.
    environment: ${{ github.event.inputs.environment || 'QA' }}
    
    Here:
    Selected environment → use it
    No value → use QA

    || 'QA' is the fallback.


steps
    Defines the individual execution steps.
    steps:



Q - What does always() mean?

    Example:

    if: always()

    This means the step should execute regardless of whether previous steps succeeded or failed.

    This is very useful for:

    Test execution
        ↓
    Test failed
        ↓
    Upload HTML report

    Even if tests fail, we still want the report.



Q - What is github.run_id?

    Example:

    name: playwright-html-report-${{ github.run_id }}

    github.run_id uniquely identifies a particular workflow run.

    So reports from different executions can have unique names.



Q - Question: Suppose I have NOT created QA, stage, or dev environments in GitHub, and 
    I only have Repository Secrets. What happens?

Answer: It will still work.

For example, if you have only these Repository Secrets:

APP_BASE_URL
APP_USERNAME
APP_PASSWORD
API_BASE_URL
API_TOKEN

then:

APP_USERNAME: ${{ secrets.APP_USERNAME }}

will read the repository-level secret.

You don't have to create a GitHub Environment just to use repository secrets.
